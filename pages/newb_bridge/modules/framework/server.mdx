## `getPlayer(src)` / `getGroups(src)` / `hasGroup(src, group, grade?, duty?)`

Cached bridge-player snapshot (job + gang). Populated on load; cleared on unload.

| Method | Signature | Returns |
| ------ | --------- | ------- |
| `getPlayer` | `(src: number \| string)` | [BridgePlayer](/newb_bridge/modules/framework#bridgeplayer)? |
| `getGroups` | `(src: number \| string)` | `table<string, number>?` |
| `hasGroup` | `(src: number \| string, group: string, grade?: number, duty?: boolean)` | `boolean` |
| `getSourceByCharId` | `(charId: string)` | `number?` |

```lua
local player = bridge.framework.getPlayer(source)
if player and player:hasGroup('police', 2, true) then end

if bridge.framework.hasGroup(source, 'ballas') then end
local src = bridge.framework.getSourceByCharId(charId)
```

## `getDutyCountJob(jobName)` / `getOnlineCountJob(jobName)` / `getJobCounts(jobName)`

| Method | Returns |
| ------ | ------- |
| `getDutyCountJob(jobName)` | `number` — players on duty |
| `getOnlineCountJob(jobName)` | `number` — players online with the job |
| `getJobCounts(jobName)` | `{ count: number, onDuty: number }` |

The host writes `GlobalState.newbsJobCounts`. Consumer copies of the framework module read that snapshot for counts (their local duty cache is never fed).

```lua
local count = bridge.framework.getDutyCountJob('police')
local online = bridge.framework.getOnlineCountJob('police')
local snapshot = bridge.framework.getJobCounts('police')
print(snapshot.count, snapshot.onDuty)
```


## `registerItemUse(itemName, cb)`

**Signature:** `registerItemUse(itemName: string, cb: fun(src: number, item: ItemUseItem)): void`

| Param | Type | Description |
| ----- | ---- | ----------- |
| `itemName` | `string` | Item name |
| `cb` | `fun(src: number, item: ItemUseItem)` | Use callback |

```lua
bridge.framework.registerItemUse('bandage', function(src, item)
    bridge.inventory.removeItem(src, item.name, 1, nil, item.slot)
    bridge.notifications.notify(src, { description = 'You feel better', type = 'success' })
end)
```

Register usable items **only** here — including when the inventory is ox_inventory. Do not add `server.export` on the item, `exports.ox_inventory:registerHook('usingItem')`, or a client `exports('itemName')` use callback. Omit `consume` on ox item defs that should stay in inventory (`consume = 0` is truthy and skips the framework use path).

The callback receives `{ name, label, metadata, slot, count }` (`metadata` is copied from `info` when needed). Hardcode any client event string inside the callback. Re-register on `onResourceStart` if the consumer can restart without a full reboot.
