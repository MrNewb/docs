A pharmacy with a `Job` block is **player-run**. Its job name has to match a real job in your framework. The sample name is `pharmacy`. Never leave a placeholder like `police` in there.

Merge the file for your framework, restart the framework core, then restart this resource. The files live in `[INSTALL]/jobs/`.

| Framework | File | Where it goes |
| --- | --- | --- |
| Qbox | `qbx_core.txt` | Merge into `qbx_core/shared/jobs.lua` |
| QBCore | `qb-core.txt` | Merge into `qb-core/shared/jobs.lua` |
| ESX Legacy | `esx.sql` | Run once against your database |
| Kora | `kora_core.txt` | Merge into the `KoraCoreSeed.jobs` table in `kora_core/shared/jobs.lua` |

The sample job has four grades: Clerk, Pharmacist, Senior Pharmacist, and Manager. The manager grade is the boss, with bank access, so the boss menu works without extra setup.

## Kora format

Kora jobs are records in a list, not a table keyed by job name. Each record carries its own `name`, and `grades` is an array where the first entry is grade 1. Add this record inside `KoraCoreSeed.jobs` in `kora_core/shared/jobs.lua`:

```lua
{
    name = 'pharmacy', label = 'Pharmacy', defaultDuty = true, offDutyPay = false, type = 'none',
    grades = {
        { name = 'Clerk',             payment = 50 },
        { name = 'Pharmacist',        payment = 75 },
        { name = 'Senior Pharmacist', payment = 100 },
        { name = 'Manager',           payment = 125, isboss = true },
    },
},
```

| Field | Meaning |
| --- | --- |
| `name` | Job name. Must match the job name on the pharmacy |
| `label` | Display name |
| `defaultDuty` | On duty when the job is assigned. `true` means the clerk does not have to clock in first |
| `offDutyPay` | A number pays that amount while off duty. `false` pays nothing |
| `type` | Service grouping. `'none'` for a normal job |
| `grades` | Array, lowest grade first. Each entry has `name` and `payment`; `isboss = true` marks the boss grade |

Kora grades start at 1, the script's grades start at 0. The bridge converts, so Clerk stays grade `0` in `/prescriptionssetup` and in any `minimumGrade` setting. Do not shift your numbers by one.

A kora_core update can overwrite `shared/jobs.lua`, so keep a copy of your addition. A resource can also register the job at runtime with `exports.kora_core:registerShared('jobs', 'pharmacy', record)`, but Kora removes records a resource registered when that resource stops, so the seed file is the safer place.

## Point the pharmacy at it

In `/prescriptionssetup`, open **Shops**, pick the pharmacy, and set the job name. If you edit the file instead, it looks like this:

```lua
Job = {
    enabled = true,
    jobName = 'pharmacy', -- must match the framework job
    minimumGrade = 0,
}
```

If you rename the job, say to `moreos`, change it in your framework **and** on every pharmacy that uses it.

## Who can do what

| Setting | What it gates |
| --- | --- |
| Medical jobs | Who can use the prescription pad. `ambulance = { minimumGrade = 0 }`, or `ambulance = true` for any grade |
| Pharmacy permission | Clocking in, the register, supply runs, and bottling |
| Pharmacy tablet permission | The pharmacy tablet: search, print, flag |
| Dispatch jobs | Who gets pinged for the panic button, forged sheets, and shoplifting |
| Overdose dispatch jobs | Who gets pinged for overdoses. `false` keeps them quiet |

Each permission is a minimum grade, with `0` as the lowest. Admin access to `/prescriptionssetup` comes from the framework admin check in Newb_Bridge.

## No player pharmacy?

Leave the job empty on the Shops page. That pharmacy becomes an NPC pharmacist who fills scripts when patients bring the paper. Sales are split between the NPC payout jobs, equally.
