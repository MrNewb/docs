## Key pictures

Every key item carries the name of a picture in its metadata (`metadata.image`), so an inventory shows the right fob without asking the server. These are in `[INSTALL]/images/` too, all 256 by 256 PNGs with a transparent background, and go in the same folder as the rest:

- `vehicle_key_<make>.png`: the car maker's own fob, one for each of the 60 makers (for example `vehicle_key_karin.png` and `vehicle_key_bravado.png`). A key for a car of that make shows it.
- `vehicle_key_smart.png`, `vehicle_key_luxury.png`, `vehicle_key_basic.png`, `vehicle_key_boat.png` and `vehicle_key_motorcycle.png`: one for each fob type. A key with no known maker shows the picture of its type.

These are the fobs themselves, not the maker logos. Some makes the game spells short (`bucking`, `dewbauch`, `principl`), and the longer spellings the locksmith picker offers map onto the same picture.

The name goes in the key's metadata without the extension:

```lua
metadata = { plate = 'ABC1234', brand = 'KARIN', image = 'vehicle_key_karin' }
```

ox_inventory, and any inventory that reads `metadata.image`, adds the folder and the `.png` itself, so the file has to be a PNG in the inventory's image folder with exactly that name. Turn this off with the **Key pictures** switch in `/setupkeys` (Keys, then Key behaviour, with Advanced on), and keys keep the plain key picture. It applies as soon as you save.

Keys that already exist keep what they have until they are used or issued again.

## Security item pictures

The seven security items have their own pictures, in the same folder: `alarm_module_linked.png`, `alarm_module_dispatch.png`, `ignition_cutoff_relay.png`, `keypad_cutoff_module.png`, `gps_tracker_module.png`, `gps_signal_jammer.png` and `tracker_extraction_kit.png`.
