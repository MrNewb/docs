## one_inventory

one_inventory keeps item definitions in its own database, not in a file you edit. You load them once with its item import, from an ox_inventory-format items file. That is `[INSTALL]/ox_inventory_items.txt`.

1. Create a folder `resources/ox_inventory_old/` and **do not** `ensure` it. It only exists so the importer can read it. Put two files in it:

   `ox_inventory_old/fxmanifest.lua`

   ```lua
   fx_version 'cerulean'
   game 'gta5'
   ```

   `ox_inventory_old/data/items.lua`

   ```lua
   return {
       -- paste the items here
   }
   ```

2. Paste the whole contents of `[INSTALL]/ox_inventory_items.txt` between the braces. If you run other Newb scripts, paste their items into the same file.
3. Copy the PNGs from `[INSTALL]/images/` into `one_inventory/web/images/`.
4. Give your admins the one_inventory admin permission in `server.cfg`, then restart:

   ```cfg
   add_ace group.admin one_inventory.admin allow
   ```

5. In game, run `/inventory:manage`, open **Migration**, and run **Import definitions**. Pick the ox_inventory source (it should show a **Files** badge), keep the item category selected, and confirm. The summary shows how many items were imported.
6. Restart `one_inventory`, then `MrNewbVehicleKeys`. Delete the `ox_inventory_old` folder.

<Callout type="info">
  Coming from ox_inventory? Rename your old `ox_inventory` folder to `ox_inventory_old`, add the entries to its `data/items.lua`, and run the same import. It brings your other items over at the same time.
</Callout>

<Callout type="warning">
  **Required:** set the inventory to `one_inventory` in the Newb_Bridge resource settings. one_inventory provides itself as `ox_inventory` and is not fully compatible with its image paths, so on `"auto"` item images do not load. See [Newb_Bridge configuration](/newb_bridge/configuration).
</Callout>

Names have to stay as they are unless you also change them in `/setupkeys`. If you rename `blank_key` in the items file and forget the locksmith shop, the shop stops selling it.

Players do not craft `vehiclekeys`. Garages, the locksmith, and admin commands hand them out. The script fills in the plate when it gives the key.

| Item | What it is |
| --- | --- |
| `vehiclekeys` | A key for one vehicle |
| `keyring` | Holds several keys |
| `lockpick` | Opens a locked door. Does not start the car |
| `advancedlockpick` | Same idea, for cars that need the better pick |
| `hotwire_kit` | Only used if hotwiring requires an item |
| `rental_paperwork` | The paper that comes with a rental |
| `aftermarket_locks` | Owner uses this to change the lock so old keys stop working |
| `blank_key` | Uncut blank. Locksmiths burn one when they cut a key |
| `keyfob_scanner` | The Pooper 9. Clones a nearby fob onto a blank, and scans a car to read its security, then bypasses its immobiliser or jams its tracker |
| `ping_transmitter` | Stick this on a car with the target option |
| `ping_receiver` | Use it to ping cars you have a tracker on |
| `alarm_module_linked` | Fit beside a parked car. Its alarm also alerts the online owner |
| `alarm_module_dispatch` | Fit beside a parked car. Its alarm alerts the owner and sends police dispatch |
| `ignition_cutoff_relay` | Fit beside a parked car. Blocks hotwiring, and a valid key is still needed to start it |
| `keypad_cutoff_module` | Fit beside a parked car. Blocks hotwiring and asks for a four digit PIN at every engine start. Turns remote start off |
| `gps_tracker_module` | Fit beside a parked car. Gives police live tracking once the car is flagged stolen or under warrant |
| `gps_signal_jammer` | Silences a fitted tracker, and the wireless side of its alarm, for a while |
| `tracker_extraction_kit` | Removes a fitted GPS tracker |

The seven security items are fitted from the inventory beside a parked, registered car with its engine off, and by default only by the mechanic and locksmith jobs (change this under **Who can fit it** on the **Vehicle security** page). Their pictures are `alarm_module_linked.png`, `alarm_module_dispatch.png`, `ignition_cutoff_relay.png`, `keypad_cutoff_module.png`, `gps_tracker_module.png`, `gps_signal_jammer.png` and `tracker_extraction_kit.png`, and ship in `[INSTALL]/images`.

On ox_inventory, `vehiclekeys` has two buttons. Throw Keys drops that key as a prop anyone can pick up. You have to be in a vehicle. Destroy Key deletes that one key. Spare copies you still have keep working. Thrown keys despawn after 30 minutes.

```lua
['vehiclekeys'] = {
    label = 'Vehicle Keys',
    weight = 50,
    stack = false,
    close = true,
    description = 'Keys for a vehicle',
    client = { image = 'vehiclekeys.png' },
    buttons = {
        {
            label = 'Throw Keys',
            action = function(slot)
                exports.MrNewbVehicleKeys:ThrowKeys(slot)
            end,
        },
        {
            label = 'Destroy Key',
            action = function(slot)
                exports.MrNewbVehicleKeys:DestroyKey(slot)
            end,
        },
    },
},
```

The full ox and QB lists are the two text files in `[INSTALL]`.

A held key looks like this:

```lua
{
    plate = 'ABC1234',
    model = -1216765807,               -- the car's model hash, 0 until the car has been seen
    modelName = 'Adder',
    brand = 'TRUFFADE',                -- the car's maker, when it is known
    image = 'vehicle_key_truffade',    -- the picture to show, see Item images
    keyType = 'smart',                 -- smart, luxury, basic, boat, motorcycle
    keyoptions = {},                   -- the fob buttons this key has
    description = 'Key for Adder, plate ABC1234',
}
```

- `lockid` is added when aftermarket locks are on.
- `brand` and `image` are added when **Key pictures** is on. `image` is the maker's fob when the maker is known, and the picture of the fob type otherwise. See [Key pictures](/mrnewbvehiclekeys/install/inventory-images#key-pictures).
- `hacked` is set on keys cloned with the scanner when **Tag cloned keys** is on. Nothing in this script reads it, so it is there for your other scripts, such as police tools, to look for.
- Keys made before this version also carry `vehName`, a second copy of `modelName`. New keys no longer have it, and a key that is renamed or migrated loses it. Everything still reads `modelName` first and falls back to `vehName`, so old keys keep working. Rental paperwork is a different item and still has its own `vehName`.
