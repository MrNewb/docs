## Where you edit

Use `/setuploottables` to edit the tables, job pay and settings. They are saved in the database. The file `configs/config.lua` only fills the database the first time the resource starts, and again if you press Reset in the panel. After that, changing the file does nothing until you reset.

The file is a server script, so players never receive it.

## Loot tables

A loot table has an id, a name and category for the panel, and a list of rows.

| Setting | Meaning |
| --- | --- |
| Table id | Lowercase letters, numbers and underscores, up to 64 characters. This is what your scripts pass to the export |
| Name and category | Only used to find the table in the panel |
| Rows | Up to 200 per table |

Each row is one possible result:

| Field | Meaning |
| --- | --- |
| Item | An item that exists in your inventory |
| Count (`min` and `max`) | The quantity is a random number between the two. At least `1` |
| Chance (`chance`) | A weight, not a percent. A row with `30` comes up three times as often as a row with `10`. A row with `0` never comes up |
| Shared (`shared`) | If on, the row is taken out of the table after it comes up once, for the whole server |
| Metadata | Optional item metadata, passed to the inventory when the item is given |

A shared row can be picked once across the whole server, not once per player. It comes back when the table is rebuilt, which happens on a restart or when you save in the panel.

You can have up to 100 tables.

## Job pay

Each job has three ranges, `low`, `mid` and `high`, each with a minimum and a maximum (up to 10,000,000).

The amount for each tier is rolled when the resource starts, and it stays the same until you change that job's ranges or restart. Saving unrelated settings does not change it. Scripts ask for a job and a tier and get the current amount.

Your scripts ask for `'low'`, `'mid'` or `'high'`. In the example config the keys are written `low_tier`, `mid_tier` and `high_tier`, but the export argument is the short name.

## Loot crates

A crate is an item that opens a loot table when a player uses it.

| Setting | Meaning |
| --- | --- |
| Crate item | The item name. One item opens one table |
| Rolls | How many rolls one crate gives, from 1 to 25 |

When a player uses a crate, LootTables rolls the table, checks the player has room for everything, takes the crate and gives the items. If there is no room, the crate is kept and the player is told. Restart LootTables after adding a new crate item, so the item becomes usable.

## Limits

| Setting | Default | Range |
| --- | --- | --- |
| Most items one roll can give | `25` | 1 to 100 |
| Largest count for one row | `1000` | 1 to 100000 |

## Logging

Every roll is recorded in a log you can watch live in the panel. You can also send it elsewhere.

| Setting | Default | Meaning |
| --- | --- | --- |
| Logging | on | Keep the roll log |
| Entries kept | `500` | How many recent rolls the panel keeps, 50 to 5000 |
| ox_lib logger | on | Also send rolls to ox_lib's logger, when you have a logging provider set |
| Discord webhook | off | Post rolls to a Discord channel |
| Log payouts | off | Also log job pay lookups |

The webhook is a secret. You paste it into the panel once, and it is stored on the server and never sent back to anyone. The panel only shows whether one is set. A valid Discord webhook URL replaces the old one, and you can clear it from the panel.

## Seed file

`configs/config.lua` holds the example data that fills the database on first start:

- `Config.LootTables` with `convenience_store`, `house_robbery`, `vehicle_search` and `dumpster`
- `Config.LootTableInfo` with the names and categories for those tables
- `Config.JobPayouts` with `taxi`, `bus`, `trucker`, `tow`, `garbage`, `mechanic`, `vineyard`, `hotdog` and `reporter`
- `Config.Utility.Debug` for console traces of every roll

The example items are stock qb-core item names. If your inventory uses different names, change them in the panel.
