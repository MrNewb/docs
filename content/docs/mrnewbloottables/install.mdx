<Callout type="warning">
  Start this **after** ox_lib, oxmysql, your framework, your inventory and Newb_Bridge, and **before** any script that calls its exports. The bridge looks at what is already running. If this script starts first, it can miss them.
</Callout>

### Dependencies [step]

[Newb_Bridge](/newb_bridge), ox_lib and oxmysql. If your scripts let LootTables give items, or you use loot crates, an [inventory the bridge supports](/newb_bridge/supported#inventory) (including `one_inventory`) has to be running too.

LootTables ships no items. Every item name in your tables must already exist in your inventory.

### Add to server.cfg [step]

Keep the folder named `MrNewbLootTables`. Swap `qbx_core` and `ox_inventory` for whatever you run.

```cfg
ensure ox_lib
ensure oxmysql
ensure qbx_core
ensure ox_inventory
ensure Newb_Bridge
ensure MrNewbLootTables
ensure your_script_that_uses_loot
```

<Callout type="info">
  **Running Kora Framework?** Follow the dedicated [Kora install](/mrnewbloottables/kora) instead of the framework steps on this page.
</Callout>

### Allow your admins [step]

The setup panel is for admins only. Give your admin group the ACE permission, in `server.cfg` or `permissions.cfg`:

```cfg
add_ace group.admin command.setuploottables allow
```

Use whichever group your admins are in. Anyone without the permission gets nothing from the panel.

### Start the server [step]

On the first start LootTables creates its own database table and fills it with the four example loot tables and nine example jobs. After that the panel owns the data. See [Configuration](/mrnewbloottables/configuration) for what each setting does.

### Open the panel [step]

In game, as an admin, type `/setuploottables`. From there you can:

- edit the example tables or make your own, picking items from your inventory's item list
- set the odds and count range for every row
- set the three pay tiers for each job
- roll a table to test it without giving anything out
- copy ready-made code for a table or a job to paste into your script

Saved changes apply immediately. The one exception is a new loot crate item: restart LootTables after adding one.

### Use it in your scripts [step]

Call the exports from the scripts that should hand out loot or pay. Working examples are on the [integration page](/mrnewbloottables/integration).

### Restart when you add a crate item [step]

Restart LootTables after adding a **new loot crate item**, because the item has to be registered as usable when the resource starts. Everything else in the panel applies as soon as you save.
