<Callout type="info">
  You need Newb_Bridge, ox_lib 3.40.2 or newer and oxmysql, plus an inventory the bridge supports if scripts give items or you use loot crates. Start LootTables after all of them and **before** any script that calls it. The full list is on [Requirements](/mrnewbloottables/requirements).
</Callout>

### Unzip it [step]

Put the `MrNewbLootTables` folder in your `resources` folder and keep that name. LootTables adds no items, so every item in your tables has to exist in your inventory already.

### Add it to server.cfg [step]

```cfg
ensure ox_lib
ensure oxmysql
ensure qbx_core          # or qb-core / es_extended
ensure ox_inventory      # or your inventory
ensure Newb_Bridge
ensure MrNewbLootTables
ensure your_script_that_uses_loot
```

### Allow your admins [step]

The panel is for admins only. Give your admin group this permission in `server.cfg` or `permissions.cfg`, using whichever group your admins are in:

```cfg
add_ace group.admin command.setuploottables allow
```

### Restart and open the panel [step]

Restart the server, join as an admin and type `/setuploottables`. The first start fills the database with four example loot tables and nine example jobs. From the panel you can edit them or make your own, set the odds and pay tiers, and roll a table to test it without giving anything out. [Configuration](/mrnewbloottables/configuration) explains each setting.

Saved changes apply at once. The one exception is a new loot crate item, which needs a LootTables restart.
