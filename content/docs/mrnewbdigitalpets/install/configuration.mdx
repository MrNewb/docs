Run `/setupdigitalpets` as an admin. That panel is where you tune everything, and **Save** applies it to every player straight away.

Use **Reset** in the panel if you want the defaults back.

## The panel

The first time you open it, a short tutorial plays. The sidebar is grouped like this:

| Group | Pages | What you decide |
| --- | --- | --- |
| Raising | Life, Needs, Care, Rarity, Goals | How long an egg takes, the level cap, how fast stats drain, what each care button restores and how long it cools down, the odds of an Ultra or Shiny hatch, and the trophies, daily streak, toy effects and style shop |
| World | Shop, Pedometer, Outings, Spots | The coin shop, step counting, landmark trips, and map zones that cheer certain species up |
| Handheld | Handheld | The display mode (UI or DUI), the prop model, the animation, and the bone it attaches to |
| General | General | Debug and the inventory item name |

Overview and Review pages sit on top as a checklist and a list of pending changes, so you can see what you are about to save.

For **Outings** and **Spots**, stand where you want the point and press the panel's position button. It grabs your coordinates and the zone name for you.

## Display modes

On the Handheld page, **Display mode** decides how the toy shows up when a player uses it.

| Mode | What the player sees |
| --- | --- |
| UI (default) | The toy opens as a normal overlay on the screen |
| DUI | The toy stays in the player's hand. A close-up camera frames the prop, the game plays on the prop's own screen, and the player clicks the printed buttons on it |

In DUI mode the controls are the printed A, B, D-pad, SELECT and POWER buttons, or the keyboard: arrow keys for the D-pad, **Z** for A, **X** for B, Enter for A, Tab or Space for SELECT, and Esc to go back or close. The Clean game works with the mouse over the screen. Z and X also work in UI mode.

A few things to know about DUI mode:

- On foot, the player is frozen in place and the hand pose is held still while the toy is open, so the camera does not sway. In a vehicle the player is not frozen
- A moment after opening, the prop is held still in front of the player. Other players see it there until the toy closes
- The screen texture of `mrnewb_takosu` is replaced for that player only, and put back when the toy closes
- After updating the files in `stream/`, restart the resource **and** fully restart the FiveM client. The client caches streamed models

## What the settings mean

You rarely need to change these, but here is what they do.

| Setting | Plain English |
| --- | --- |
| `Item` | The inventory item name. Defaults to `digital_pet` |
| `StarterName` | The name shown before a player renames their pet |
| `HatchMinutes` | How long the egg waits before hatching. Default 15 |
| `MaxLevel` | Level cap. Default 50 |
| `DaysUntilDeath` | Real days of neglect before the pet dies. Default 30 |
| `NeedDrain` | For each need, how often (`Every`, seconds) it drops and by how much (`Lose`) while the toy is closed |
| `Care` | For each button, how much it restores (`Fill`), the cooldown in seconds (`Wait`), and the XP it gives (`Xp`) |
| `Rarity` | Percent chance of `Ultra` and `Shiny`. Ultra is rolled first |
| `Shop` | `Enabled`, plus the item list. Each item needs a unique `id`, a `label`, a `cost` in pet coins, and a `happiness` value |
| `Pedometer` | `Enabled`, the steps needed for the Walk bonus, and the soft session goal |
| `Outings` | `Enabled`, the cooldown, arrival radius, whether it sets a waypoint, the reward, and the list of places |
| `FavoriteSpots` | `Enabled`, the happiness tick, its cooldown, and zones tied to a species trait (`beach`, `city`, or `wild`) |
| `Handheld` | Prop models, a fallback, the animation, the bone, and `DisplayMode` (`ui` or `dui`) |
| `Streak`, `Trophies`, `Toys`, `Style` | The Goals page: the daily care streak rewards, the trophy payout, whether toys have effects, and the style shop (hats, shells, scenes) |
| `Debug` | Extra logging. Off by default. Set it on **General > Debug output** in the panel. It prints plain one-line messages with names, ids and numbers, as `[MrNewb_DigitalPets:server] area: text` or `[MrNewb_DigitalPets:client] area: text`. Leave off on a live server |

Custom shop items can use an `https://` image or a `nui://<resource>/...` path. The stock toys use bundled art.

## Commands

| Command | Who | What it does |
| --- | --- | --- |
| `/setupdigitalpets` | Admin (framework admin or `group.admin`) | Opens the setup panel |
| `/givealldigitalpets` | `group.admin` | Gives you one hatched pet of every species. Handy for testing |

Players have no commands. They just use the item.

## Giving pets from other scripts

A pet is just an item, so add it the way you would add any other.

```lua
-- inventory agnostic, through Newb_Bridge
bridge.inventory.addItem(source, 'digital_pet', 1)

-- or ox_inventory directly
exports.ox_inventory:AddItem(source, 'digital_pet', 1)
```

It arrives as an egg and hatches after `HatchMinutes`. You can sell it in any shop script, hand it out as a job reward, or drop it in loot like a normal item.

Events and callbacks that start with `MrNewbDigitalPets:` are the UI talking to the server. Do not build on them.
