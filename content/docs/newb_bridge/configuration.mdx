Open `settings/bridge_resources.lua` in the Newb_Bridge folder. Set a value to a resource name to pin it, or leave `"auto"` and the bridge uses the first supported resource that is started. Every setting ships as `"auto"`. Notifications, fuel, and dispatch fall back to a built-in `internal` provider when nothing else is installed; the rest do nothing until a supported resource is running.

```lua
Config = {}

Config.Debug = false
Config.VersionCheck = true

Config.Framework = "auto"
Config.Inventory = "auto"
Config.Target = "auto"
Config.VehicleKeys = "auto"
Config.VehicleFuel = "auto"
Config.Menu = "auto"
Config.Notifications = "auto"
Config.Inputs = "auto"
Config.TextUI = "auto"
Config.ProgressBar = "auto"
Config.BossMenu = "auto"
Config.Dispatch = "auto"

Config.TaskGroups = {
    DefaultMaxPlayers = 8,
    MaxMaxPlayers = 8,
    MinMaxPlayers = 2,
    DefaultImage = '',
    InviteRadius = 10.0,
    JoinCodeLength = 6,
    MaxNameLength = 32,
}
```

<Callout type="warning">
  **Using one_inventory? You must set `Config.Inventory = "one_inventory"`.** Do not leave it on `"auto"`. one_inventory provides itself as `ox_inventory`, so auto-detect treats it as ox_inventory and builds ox_inventory image paths (`nui://ox_inventory/web/images/...`). one_inventory is not fully compatible with those paths, so item images do not load, and shops can fail to open. Pinning it makes the bridge use the one_inventory module and `one_inventory/web/images/`.

  ```lua
  -- Newb_Bridge/settings/bridge_resources.lua
  Config.Inventory = "one_inventory"
  ```

  Restart Newb_Bridge and every script that uses it after changing this.
</Callout>

| Setting | What it does |
| --- | --- |
| `Config.Debug` | Extra debug lines in the console. Leave `false` in production. |
| `Config.VersionCheck` | Checks GitHub on start and prints newer versions to the **server console only**. Set `false` to silence it. |
| `Config.TaskGroups` | Limits for the party/task group menu (max players, invite radius, join code length). |

## Auto-detection

When a setting is `"auto"`, Newb_Bridge walks the list in order and picks the first resource that is `started`. If none are started yet (bridge init can run before dependents), it picks the first whose state is not `"missing"`. If still nothing, it uses the module `fallback` when one exists.

Start order in `server.cfg` matters. Bridged resources should be running before scripts that depend on them. On start, the server console prints one line per module (`auto`, `manual`, or `auto, fallback`).

Valid values for each setting, in check order: [Supported](/newb_bridge/supported).

## Theme

`settings/theme.lua` holds one color palette used by every Newb UI: backgrounds, text, buttons, status colors, corner radius and font. Change a value, restart `Newb_Bridge`, then restart or reopen the resources that use it. Leave a token out and each resource keeps its own built-in color. Colors are `#rgb` or `#rrggbb`; tokens marked `(any)` in the file also accept `rgb()` and `rgba()`.

Developers can read it with `exports.Newb_Bridge:GetTheme()` or `GetThemeCss()`. See [Utilities](/newb_bridge/developers/utilities#theme).

## Locales

Newb_Bridge reads the locale ox_lib is already using, so there's nothing to set per script and no locale option of its own. Set `ox:locale` once in `server.cfg` and every resource that uses the bridge follows it:

```cfg
setr ox:locale en
```

Missing codes fall back to `en`. Full list: [Supported](/newb_bridge/supported#locales).

## Configuration examples

### Pin providers

Use when auto-detect picks the wrong resource (for example both `qs-inventory` and `ox_inventory` are running). Set only the ones you need:

```lua
-- Newb_Bridge/settings/bridge_resources.lua
Config.Inventory = "ox_inventory"
Config.Framework = "qbx_core"
Config.Target = "ox_target"
Config.Notifications = "ox_lib"
```
