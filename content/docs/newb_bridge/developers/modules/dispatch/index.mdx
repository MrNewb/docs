Server-side dispatch alerts that route through the configured provider (`Config.Dispatch`). When it resolves to `internal` (the built-in version), Newb_Bridge notifies eligible on-duty players with a blip + notification.

- [Client](/newb_bridge/developers/modules/dispatch/client) — host internal-alert listener (consumer noop)
- [Server](/newb_bridge/developers/modules/dispatch/server) — `sendAlert`

`Config.Dispatch` is `"auto"` by default. Auto-detect order: `ps-dispatch` → `cd_dispatch` → `tk_dispatch` → `rcore_dispatch` → `lb-tablet` → `origen_police` → `core_dispatch` → `kartik-mdt` → `codem-dispatch` → `wasabi_mdt` → `redutzu-mdt`. When none is installed it falls back to `internal`.

`wasabi_mdt` receives the documented `CreateDispatch` fields only (type, title, description, location, coords, priority, code and sender). It has no department filter, so the `jobs` argument does not narrow who sees the call.

```lua
-- Server
bridge.dispatch.sendAlert(src, { 'police', 'sheriff' }, storeCoords, {
    title = 'Store Robbery',
    description = 'Armed robbery in progress',
    code = '10-31',
}, {
    sprite = 161,
    scale = 1.2,
    colour = 1,
    text = 'Robbery',
}, true)
```
