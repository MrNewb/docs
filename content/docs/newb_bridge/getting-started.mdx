Newb_Bridge lets MrNewb scripts work with whatever framework, inventory and target your server runs. You install it once, and every MrNewb script uses it.

### Download it [step]

Get the newest build from the [Releases page](https://github.com/MrNewb/Newb_Bridge/releases/latest) and unzip it into your `resources` folder. Keep the folder named **`Newb_Bridge`**.

You also need [ox_lib](https://github.com/overextended/ox_lib), [oxmysql](https://github.com/overextended/oxmysql), and a framework and inventory from the [Supported](/newb_bridge/supported) list.

### Add it to server.cfg [step]

Put `ensure Newb_Bridge` **after** your framework, inventory and target, and **before** any MrNewb script.

```cfg
ensure ox_lib
ensure oxmysql
ensure qbx_core          # or qb-core / es_extended
ensure ox_inventory      # your inventory
ensure ox_target         # your target
ensure Newb_Bridge

# your MrNewb scripts go below
ensure MrNewbVehicleKeys
```

### Restart and check [step]

Restart the server. That is all most servers need, because the bridge finds your resources by itself.

If the console shows a yellow `No installed provider found for ...` line, a part could not find a matching resource. You can ignore it for parts you do not use. Otherwise see [Troubleshooting](/newb_bridge/troubleshooting).

## Notifications are built in

You do not need a notification resource. If you have none installed, the bridge shows its own: four types, markdown in the text, and item images.

<img src="/docs/images/newb_bridge/notifications.gif" alt="Newb_Bridge built-in notifications sliding in: success, info, warning, error and an item with an image" />

If you already run a notification resource such as ox_lib or okokNotify, the bridge uses that instead. To always use the built-in ones, set `Config.Notifications = "internal"` in `settings/bridge_resources.lua` ([Configuration](/newb_bridge/configuration)).
