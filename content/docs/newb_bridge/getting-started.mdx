<Callout type="warning">
  Start Newb_Bridge **after** ox_lib, your **framework**, **inventory**, **target**, and anything else it has to talk to. If those come up later, it can miss them and you’ll get the wrong provider, or none. **Don’t** start Newb_Bridge before the framework. Scripts that import `@Newb_Bridge/import.lua` have to start **after** the bridge. `import.lua` errors if the bridge ain’t running.
</Callout>

### Requirements [step]

[ox_lib](https://github.com/overextended/ox_lib), [oxmysql](https://github.com/overextended/oxmysql), and a framework, inventory, and target from [Supported](/newb_bridge/supported). That inventory list includes `one_inventory`. Every provider defaults to `"auto"`. You only need the ones your server actually runs: notifications, fuel, and dispatch fall back to built-in versions when nothing else is installed.

### Get the resource [step]

Grab the newest build from the [Releases page](https://github.com/MrNewb/Newb_Bridge/releases/latest) and unzip it into `resources`. Keep the folder named **`Newb_Bridge`**, because `import.lua` finds the bridge by that name.

### Add to server.cfg [step]

```cfg
ensure ox_lib
ensure oxmysql
ensure qbx_core          # or qb-core / es_extended
ensure ox_inventory      # your inventory
ensure ox_target         # optional; any other bridged resource too
ensure Newb_Bridge

# scripts that use bridge.*
ensure your_script
```

### Configure [step]

Leave providers on `"auto"` in `settings/bridge_resources.lua`, or pin them. Optional. Set the language once with `setr ox:locale en` in `server.cfg` (the bridge follows ox_lib's locale).

### Check it works [step]

Restart the server and read the console. The bridge prints which provider each module resolved to, and a yellow `No installed provider found for ...` line for anything it could not match. A module you never use does not need a provider. If something looks wrong, see [Troubleshooting](/newb_bridge/troubleshooting). Details on pinning: [Configuration](/newb_bridge/configuration).
